# Plan — Do Now .tex editing parity

## Why

Student / Teacher / Slides each have a `.tex` editor button in the web app with Save + Rebuild. Do Now just added the PDF preview but NOT the editor. Registry prompts have partial-LaTeX bugs (e.g. L63_P1 Do Now #1's `\begin{aligned}` missing its math-mode wrapper; L64_P1 already hand-patched after pdflatex failures). Editing directly in the web app saves a round-trip.

## Scope

Four files. Follow the exact pattern of the existing student/teacher/slides editor — **no new concept**. Do Now is a fourth `edition` in an enumeration that already flows through Supabase column → Railway PUT → pdflatex → Supabase Storage.

### 1. Migration — `supabase/migrations/006_tex_do_now.sql`

```sql
ALTER TABLE lesson_planning.lessons
  ADD COLUMN IF NOT EXISTS tex_do_now TEXT;
```

That's it. No RLS change (inherits from lessons). Idempotent.

### 2. Seed — `supabase/seed.py`

- Extend `base_row()` to include `"tex_do_now": None, "has_tex_do_now": False` (the `has_tex_do_now` field is local-only; don't send to DB unless there's already a column for it — there isn't, so drop it. Just `tex_do_now`).
- Extend the `_globs` helper to include `do_now.tex` alongside student/teacher/slides.
- Add a new per-file loader block mirroring the existing ones:
  ```python
  for tex in _globs("do_now.tex"):
      lid = tex.stem.removesuffix("_do_now")
      row = rows.setdefault(lid, base_row(lid))
      row["tex_do_now"] = tex.read_text(encoding="utf-8")
  ```
- NO `has_pdf_do_now` handling. The web app uses HEAD-probe, not a lessons column, so leave the PDF presence out of the lessons table. Just the tex source.

### 3. Railway — `railway/server.py`

- `EDITIONS = {"student", "teacher", "slides", "do_now"}`.
- `_validate_edition` error message: update to include `'do_now'`.
- `_rest_get_lesson` select clause: add `tex_do_now` so the build endpoint sees it.
- Add `tex_do_now = row.get("tex_do_now")` in the build handler.
- Include it in the early `nothing to build` guard: `if not yaml_text and not tex_student and not tex_teacher and not tex_slides and not tex_do_now`.
- Add a build block right after slides (mirror the slides pattern — do_now is independent; missing `tex_do_now` is NOT a failure of the full build):
  ```python
  do_now_ok = False
  if tex_do_now:
      do_now_tex_path = tmp / f"{lesson_id}_do_now.tex"
      do_now_tex_path.write_text(tex_do_now, encoding="utf-8")
      do_now_ok, do_now_log = _run_pdflatex(do_now_tex_path.name, tmp)
      if not do_now_ok:
          log.warning("do_now build failed for %s: %s", lesson_id, do_now_log[-500:])
          if not log_tail:
              log_tail = do_now_log
  ```
- Add upload block (mirror slides upload):
  ```python
  if do_now_ok:
      pdf_path = tmp / f"{lesson_id}_do_now.pdf"
      if pdf_path.exists():
          # match the existing upload signature / pattern exactly
          ...
          pdf_do_now_url = ...
  ```
- Return `pdf_do_now_url` in the response dict alongside student/teacher/slides urls.
- **PUT /tex/:id/:edition** already accepts any edition matching `EDITIONS` — since we added "do_now" to that set, PUT automatically works. Verify by tracing the code — if the PUT handler hardcodes column names, add "do_now" there too.

### 4. Web — `web/index.html` + `web/js/main.js`

**`web/index.html`** — add a fourth navy `.tex` button right after Slides .tex:
```html
<button id="btn-tex-do-now" class="btn btn-navy">Do Now .tex</button>
```

**`web/js/main.js`**:
- Add `const btnTexDoNow = document.getElementById("btn-tex-do-now");`
- Extend `highlightToolbarBtn` to toggle the new button on `"tex-do_now"`.
- Add event listener: `btnTexDoNow.addEventListener("click", () => openTexView("do_now"));`
- `openTexView(edition)` already takes the edition string and builds the label. Check it works with `"do_now"` as the edition value — it should pass through transparently. The only likely friction is the label rendering (`${activeLessonId} / do_now` — acceptable). If you want to prettify the label to "Do Now" for display, make that an isolated formatting decision in `openTexView`.
- Keep the button enabled even when there's no stored tex — the editor shows "(no do_now tex stored yet)" the same way the other editions do.

**Do NOT touch** `api.js` `getTex` / `saveTex` — they already parameterize on `edition`.

## Non-goals

- Do NOT add PDF rebuild logic specific to do_now — the unified `/build/:id` endpoint rebuilds all editions the lesson has tex for; that's enough.
- Do NOT change the `% GENERATED by build_do_now_tex.py` header behavior. The header lives in the Supabase tex_do_now value too after seed. Web edits preserve it (it's just a comment). Users who want to regenerate locally can still use `--force`.
- Do NOT add a "Download do_now.tex" button or CodeMirror upgrade — plain textarea matches existing pattern.

## Watch for these failure modes

- **CHECK constraint on columns** — lessons may have a `tex_{student,teacher,slides}` check somewhere. Grep `supabase/schema.sql` + earlier migrations; if present, update to include `tex_do_now`. (Probably not present; the schema uses plain TEXT columns.)
- **PostgREST column reload** — after migration 006, PostgREST may need a schema-cache refresh. The usual workaround: Supabase dashboard → Settings → API → Reload schema. Document this in the commit/plan for the user.
- **Passcode + identity headers** already flow through — reuse.
- **Railway `_validate_edition` 400 message** — leaking an outdated list confuses. Update it.
- **Railway `_rest_get_lesson` select may hardcode columns** in a single query string — add `tex_do_now` there, verify no `*` usage would silently cover it.
- **Dockerfile** doesn't hardcode editions — trust. Don't touch.

## Testing

After migration + redeploy:
1. In Supabase SQL editor run `006_tex_do_now.sql`. (Or alternatively: `ALTER TABLE lesson_planning.lessons ADD COLUMN IF NOT EXISTS tex_do_now TEXT;` directly.)
2. Click API → Reload schema (or wait ~60s).
3. `python supabase/seed.py` — should report lessons: 19/19, now with tex_do_now populated.
4. Railway auto-redeploys on push (already set up). Wait for it.
5. Reload `/?lesson=L63_P1` in web. Click "Do Now .tex" — textarea shows the tex source with the 3 bankitems and the (currently broken) `\begin{aligned}` block.
6. Edit — wrap the aligned block in `\[...\]`. Click "Save & Rebuild PDF".
7. Click "Do Now" teal button — the rebuilt PDF loads, no longer showing the error.
